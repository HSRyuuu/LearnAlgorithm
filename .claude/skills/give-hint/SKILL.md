# Algorithm Hint - 단계별 힌트 스킬

사용자가 알고리즘 문제를 풀다 막혔을 때, 현재 작성 중인 코드를 분석하여 3단계 힌트를 제공한다.

## 동작 원리

1. 사용자가 현재 편집 중인 Java 파일(또는 가장 최근 수정된 solution 파일)을 찾는다
2. `solution()` 메서드 내에서 `// hint` 주석(대소문자 무관)을 찾는다
3. Javadoc 헤더(`@Algorithm`)와 동일 이름의 `.md` 파일에서 문제 정보를 파악한다
4. 사용자가 이미 작성한 코드를 읽고, **어디까지 진행했는지** 파악한다
5. 3단계 힌트를 순서대로 제공한다

## 힌트 제공 규칙

### 반드시 지켜야 할 것

- **코드 샘플 금지**: 의사코드, 실제 코드 조각, 구현 예시를 절대 보여주지 않는다. 자연어로만 설명한다.
- **사용자 코드 존중**: 사용자가 이미 작성한 부분은 올바르다고 가정한다. 힌트는 `// hint` 이후, 아직 작성하지 않은 부분에 초점을 맞춘다.
- **점진적 공개**: Level 1부터 순서대로 보여준다. 사용자가 "더 힌트 줘", "다음 힌트" 등을 요청하면 다음 레벨을 보여준다.
- **한국어 사용**: 힌트는 한국어로 작성한다. 알고리즘 용어(HashMap, BFS 등)는 영문 그대로 사용해도 된다.

### Level 1: 방향 제시 (최소한의 힌트)

이 문제를 풀기 위해 **어떤 관점으로 바라봐야 하는지**만 알려준다.
- 핵심 아이디어를 한 문장으로 요약
- 어떤 성질이나 패턴을 활용해야 하는지 암시
- 예: "각 종류별로 '안 입는 경우'도 하나의 선택지로 생각해 보세요."

형식:
```
💡 **Level 1 힌트**
{한두 문장의 방향 제시}
```

### Level 2: 접근법 설명 (조금 더 구체적)

Level 1의 아이디어를 **어떻게 적용하는지** 논리적 흐름을 설명한다.
- 문제를 어떤 단계로 나눌 수 있는지
- 어떤 수학적/논리적 원리가 적용되는지
- 사용자가 이미 작성한 코드와 연결하여 "여기까지는 되었으니, 다음은 이런 방향"으로 안내

형식:
```
💡 **Level 2 힌트**
{접근법을 2~4문장으로 설명}
```

### Level 3: 구체적 전략 (거의 답에 가까운 힌트)

구현에 필요한 **구체적인 논리 흐름**을 단계별로 서술한다. 코드는 여전히 보여주지 않지만, 이 설명을 읽으면 바로 구현할 수 있을 정도로 상세하게 안내한다.
- 어떤 값을 계산/누적해야 하는지
- 어떤 조건을 처리해야 하는지
- 최종 결과를 어떻게 도출하는지

형식:
```
💡 **Level 3 힌트**
{구체적인 풀이 전략을 단계별로 서술}
```

## 워크플로우

1. **파일 찾기**: IDE에서 열린 파일 또는 가장 최근 수정된 `src/Algorithm/**/*.java` 파일을 찾는다
2. **코드 읽기**: 해당 Java 파일을 읽어 `// hint` 주석 위치와 사용자가 작성한 코드를 파악한다
3. **문제 파악**: Java 파일과 동일한 이름의 `.md` 파일(예: `Hash_Disguise.java` → `Hash_Disguise.md`)이 같은 폴더에 존재한다. 이 파일에 문제 설명, 제한 조건, 입출력 예시가 있으므로 반드시 읽어서 문제를 이해한다
4. **레퍼런스 확인**: `learning-algorithm` 스킬의 `references/` 폴더에서 해당 알고리즘 레퍼런스를 읽는다
5. **Level 1 힌트 출력**: 첫 호출 시 Level 1만 출력한다
6. **추가 힌트**: 사용자가 더 요청하면 Level 2, Level 3을 순서대로 출력한다

## 디버깅 안내 모드

사용자가 "왜 안돼?", "왜 틀려?", "뭐가 잘못된 거지?", "어디가 문제야?" 등 자신의 코드가 왜 동작하지 않는지 질문하는 경우에 활성화된다.

### 힌트 모드와의 차이

- **힌트 모드**: `// hint` 이후 아직 작성하지 않은 부분에 초점 → 사용자 코드를 올바르다고 가정
- **디버깅 모드**: 사용자가 이미 작성한 코드에서 논리적 오류나 실수를 찾아 안내 → 사용자 코드에 문제가 있다고 가정

### 디버깅 워크플로우

1. Java 파일을 읽고 `solution()` 메서드의 전체 코드를 파악한다
2. 문제 설명 `.md` 파일을 읽어 정확한 요구사항을 이해한다
3. 테스트 케이스(`main` 메서드)의 입력/기대값과 코드 로직을 대조한다
4. 오류 원인을 찾아 자연어로 안내한다

### 디버깅 안내 규칙

- **코드 수정은 하지 않는다**: 어디가 왜 잘못되었는지만 말로 설명한다. 수정된 코드를 보여주지 않는다.
- **구체적 위치를 알려준다**: "몇 번째 줄의 어떤 부분"처럼 문제 지점을 특정한다.
- **왜 잘못인지 설명한다**: 단순히 "여기가 틀렸다"가 아니라, 어떤 입력일 때 어떤 결과가 나오는지 예시를 들어 설명한다.
- **한 번에 하나씩**: 오류가 여러 개여도 가장 근본적인 것 하나만 먼저 알려준다. 사용자가 수정 후 다시 물어오면 다음 오류를 안내한다.

### 출력 형식

```
🔍 **디버깅 안내**
{어디가 잘못되었는지, 왜 잘못인지를 자연어로 설명}
```

## 주의사항

- `// hint` 주석이 없으면 사용자에게 "solution() 메서드에서 막힌 지점에 `// hint` 주석을 남겨주세요"라고 안내한다
- 여러 개의 `// hint`가 있으면 가장 마지막(가장 아래) 것을 기준으로 힌트를 제공한다
- 사용자가 Level을 지정하면(예: "Level 3 힌트 줘") 해당 레벨부터 보여준다
- `.md` 문제 파일을 찾지 못하면 사용자에게 "문제 설명 파일을 찾지 못했습니다. 문제 파일 경로를 알려주시겠어요?"라고 물어본다
- Java 파일 자체를 특정할 수 없는 경우(IDE에서 열린 파일 정보가 없고, 최근 수정된 solution 파일도 없는 경우) "어떤 문제의 힌트가 필요한가요? 파일 경로를 알려주세요"라고 물어본다
