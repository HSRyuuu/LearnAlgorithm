# Review Solution - 알고리즘 풀이 리뷰 스킬

사용자가 알고리즘 문제를 풀고 나서, 완성된 코드의 허점과 개선점을 리뷰한다.

## 리뷰 항목

### 1. 정확성 검증

- 문제 요구사항을 정확히 충족하는지 확인
- 테스트 케이스를 실행하여 통과 여부 확인
- 엣지케이스 누락 여부 점검:
  - 빈 입력, 단일 원소, 최댓값/최솟값 경계
  - 모든 원소가 동일한 경우
  - 음수, 0, 오버플로우 가능성

### 2. 시간 복잡도 분석

- `solution()` 메서드의 시간 복잡도를 Big-O로 표기
- 반복문 중첩, 재귀 호출, 자료구조 연산 등을 기반으로 산출
- 문제의 제한 조건 대비 통과 가능 여부 판단
- 더 나은 시간 복잡도가 존재하면 언급

### 3. 공간 복잡도 분석

- 추가로 사용하는 자료구조의 공간 복잡도를 Big-O로 표기
- 불필요한 메모리 사용이 있으면 지적

### 4. 코드 허점

- 논리적 오류나 잠재적 버그
- off-by-one 에러, 타입 캐스팅 문제
- 불필요한 연산이나 중복 코드

## 리뷰 워크플로우

1. IDE에서 열린 파일 또는 가장 최근 수정된 `src/Algorithm/**/*.java` 파일을 찾는다
2. Java 파일과 동일한 이름의 `.md` 파일(예: `Hash_Disguise.java` → `Hash_Disguise.md`)을 읽어 문제 요구사항을 파악한다
3. `solution()` 메서드의 코드를 분석한다
4. 테스트 케이스를 실행하여 통과 여부를 확인한다
5. 리뷰 결과를 출력한다

## 출력 형식

```
📋 **풀이 리뷰**

**정확성**: {PASS/FAIL} - {간단한 설명}

**시간 복잡도**: O(...) - {산출 근거 한 줄}
**공간 복잡도**: O(...) - {산출 근거 한 줄}

**허점/개선점**:
- {있으면 나열, 없으면 "발견된 허점 없음"}
```

## 리뷰 규칙

- **간결하게**: 장황하지 않게 핵심만 짚는다
- **코드 수정은 하지 않는다**: 문제점을 지적만 하고, 수정은 사용자 몫이다
- **칭찬도 한다**: 잘 작성된 부분이 있으면 간단히 언급한다
- **더 나은 풀이가 있으면**: "다른 접근법으로 O(N)에 풀 수 있습니다"처럼 존재 여부만 알려주고, 구체적 코드는 보여주지 않는다. 사용자가 요청하면 그때 설명한다.

## 주의사항

- 문제 파일(`.md`)을 찾지 못하면 사용자에게 경로를 물어본다
- Java 파일을 특정할 수 없으면 어떤 파일을 리뷰할지 물어본다
- `give-hint` 스킬과 달리, 이 스킬은 완성된 코드를 대상으로 한다. `solution()`이 아직 비어있으면 "아직 풀이가 작성되지 않은 것 같습니다"라고 안내한다
